# AIChess

A modern, playable chess website where you face **free and configurable AI models** (Google Gemini, OpenRouter free routes) plus a **built-in Stockfish** engine — all in the browser, deployable on GitHub Pages.

**Live:** `https://ziyyhhk.github.io/AIChess/` (published from the `docs` folder of `main`)

```bash
git clone https://github.com/ziyyhhk/AIChess.git
cd AIChess
npm install --legacy-peer-deps
```

Open the URL Vite prints (usually `http://localhost:5173/AIChess/`).

## Sounds

Every sound is generated by `scripts/generate-sounds.mjs` and committed under
`public/sounds/`, so the app never has to fetch a third-party CDN to play a move:

```bash
node scripts/generate-sounds.mjs   # deterministic: re-running changes nothing
```

| Game event | File |
|---|---|
| New game | `game-start.wav` |
| Player move / AI move | `move-self.wav` / `move-opponent.wav` |
| Capture | `capture.wav` |
| Castling | `castle.wav` |
| Check (player / opponent) | `move-self-check.wav` / `move-opponent-check.wav` |
| Check (either side, generic) | `move-check.wav` |
| Promotion | `promote.wav` |
| Premove queued | `premove.wav` |
| Illegal move attempt | `illegal.wav` |
| Game end / win / loss / draw | `game-end.wav`, `game-win-long.wav`, `game-lose-long.wav`, `game-draw.wav` |
| Notification / button click | `notify.wav` / `click.wav` |
| Ten seconds left | `tenseconds.wav` (shipped; unused until a clock feature exists) |

Design rules that make them reliable:

- sounds are triggered from **one** place — the move pipeline in `src/App.tsx`
  (`commitMove`) — never from a click handler, a render or an animation
  callback;
- every committed move produces one sound plan, deduplicated by a move key
  (`position + move`), so re-renders, StrictMode double effects, board flips and
  animation callbacks cannot replay it;
- a move that is still loading is **retried** as soon as the audio element can
  play, instead of being silently dropped;
- playback is queued until the first user gesture (browser autoplay rules);
- the choice depends on *who* moved and what happened, never on which piece
  moved, so a pawn move sounds exactly like a knight move.

Settings hold a sound toggle, master volume and a pack selector. The optional
"Chess.com files" pack streams Chess.com's public MP3s at runtime — those files
are **not** part of this repository and their licence for redistribution has not
been verified.

## Piece animation

A committed move creates an animation request in the move pipeline
(`src/App.tsx`) carrying the move id, the moving piece and (for drags) the drop
point. `ChessBoard` turns that into flights
(`src/components/board/flights.ts`), hides the destination square and renders the
real piece image travelling across the board with the Web Animations API:

- the piece element is exactly one square wide and is moved with
  `translate3d(x * 100%, y * 100%, 0)`, so one square of travel is exactly 100%
  at every board size and after any resize or flip;
- everything happens in a layout effect, before the browser paints the new
  position, so there is no frame where the piece is already on its target square;
- castling animates king **and** rook, a promotion travels as a pawn, a dragged
  piece continues from where it was released, and a queue of rapid moves never
  cancels a piece mid-flight without settling it;
- `prefers-reduced-motion` and the "Slide animation" setting skip the travel and
  place the piece immediately.

## AI thinking time and premoves

Settings → *Play* → **AI thinking time**: `Instant`, `Natural` (varies with
difficulty) or a custom delay.

```
wait = max(engine response time, target thinking time)
```

The engine (or hosted model) starts immediately; the wait only delays *showing*
an already-computed move so there is room to premove. A slow engine is never
delayed further. Targets: Beginner 0.7–1.2 s, Easy 0.8–1.5 s, Medium 1.0–2.0 s,
Hard 1.2–2.7 s, Expert 1.5–3.5 s, randomised inside the range.

While the opponent is thinking you can select a piece and click or drag a
destination: the move is stored as a premove (highlighted, one `premove.wav`),
never applied to the position, and never reported as illegal. When the
opponent's move has landed *and its animation has finished*, the premove is
re-validated against the new position — if it is still legal it plays with the
normal animation and sound, otherwise it is discarded silently.

## Game analysis

`Analysis` in the sidebar, or **Analyse game** in the game panel.

- Takes a **snapshot** of the current move history; the live game is never
  touched, and analysis runs in its own engine worker, so it cannot interrupt
  the engine that is playing.
- Rebuilds every position from the real moves and searches each one (MultiPV 2
  for the position before the move, so the second-best line is known). Because
  the position after move N is the position before move N+1, a game of N moves
  needs N+1 searches at a consistent depth.
- Shows progress (`Analysing move 18 of 42`), supports cancelling (partial
  results are kept), and reports failures with a retry instead of pretending.
- Move grades are AIChess's own heuristics over real engine numbers — *not*
  Chess.com's proprietary algorithm. Thresholds live in one place
  (`src/analysis/classification.ts`).
- Accuracy is AIChess's own estimate (`100 · e^(-loss/400)` per move, averaged
  per side, book and forced moves excluded) and is labelled as such in the UI.

| Grade | Criterion |
|---|---|
| Forced | The only legal move |
| Book | A known opening position (small embedded list) and the engine agrees |
| Brilliant | Engine's top move, offers ≥ 1 point of material that can be captured, still ≥ +1.00 |
| Great | Engine's top move with a ≥ 1.50 gap to the second-best line |
| Best | Matches the engine's choice, or loses ≤ 0.12 |
| Excellent / Good | Loses ≤ 0.35 / ≤ 0.80 |
| Inaccuracy / Mistake / Blunder | Loses ≤ 1.60 / ≤ 3.20 / more |
| Miss | A forced mate or a winning position (≥ +2.00) was let slip without losing |

Mate scores are kept separate from centipawns (`mate 0` = the side to move is
mated), and "critical position" is a position flag (one move is clearly
strongest), not another word for blunder.

### Analysis icons

The ten classifications use original vector glyphs drawn in
`src/components/analysis/MoveGlyph.tsx` — no emoji, no external requests. To use
your own icon set, drop files into `public/assets/analysis/` (see the README in
that folder) and they are picked up automatically; every grade also carries a
text label, so colour is never the only signal.

The ten Chess.com icon URLs that were requested could not be downloaded in the
environment this was built in (that host is unreachable from it), so they were
never inspected and are **not** redistributed here. `public/assets/analysis/`
takes them as a drop-in if you have the right to use them.

## PGN export

**Copy PGN** and **Download PGN** in the game panel export the real current
game using chess.js's own serialisation (correct SAN, captures, castling, en
passant, promotion, check/checkmate) with `Event`, `Site`, `Date`, `Round`,
`White`, `Black` and `Result` headers and the right result token (`1-0`, `0-1`,
`1/2-1/2`, `*`). Copying reports success only after the clipboard call succeeds,
falls back to a temporary textarea, and downloading writes
`aichess-game-YYYY-MM-DD.pgn`.

## AI providers

### Stockfish (no key)

`public/engines/stockfish.js` is a placeholder. When no full engine build is
present the app loads `stockfish.js` 10.0.2 from jsDelivr as a blob worker.
To host the engine yourself, put a full single-file build (over 5 KB) at
`public/engines/stockfish.js`; Stockfish is GPL-licensed, so check that licence
before committing a copy to this MIT-licensed repository.

Analysis uses a second, separate worker and falls back to a small built-in
search (`src/engine/miniEngine.ts`, original code) when no engine can be loaded —
labelled in the UI as the offline fallback, never presented as Stockfish.

### Google Gemini / OpenRouter (your API key)

1. Create a key (Google AI Studio, or openrouter.ai).
2. Open **Settings** in AIChess → paste the key → Save.
3. Choose a model under **AI Opponents**.

### Security

- This is a **static** site. Anything shipped in the JS bundle is public.
- **Never** commit API keys. Keys live in memory for the browser session only.

## GitHub Pages deployment

The live site is published from the **`docs` folder on `main`**
(Settings → Pages → *Deploy from a branch*, branch `main`, folder `/docs`).

`.github/workflows/deploy.yml` rebuilds the site on every push to `main` and
commits the result back into `docs/` (with `.nojekyll`), which is exactly the
folder that source publishes. It also uploads the build as a Pages artifact.
Because the workflow pushes `docs/` itself, no manual copy step is needed:

```bash
npm run build
rm -rf docs && mkdir docs && cp -r dist/* docs/ && touch docs/.nojekyll
```

Vite is configured with `base: '/AIChess/'`, so all runtime asset references —
bundles, CSS, piece artwork, `sounds/`, `assets/analysis/`, `engines/` — resolve
under the repository sub-path. If you rename the repository, change `base` in
`vite.config.ts` to match.
